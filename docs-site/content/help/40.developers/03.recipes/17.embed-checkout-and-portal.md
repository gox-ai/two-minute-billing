This recipe continues [Checkout and portal](/help/developers/recipes/checkout-and-portal). The
sessions are the same. Here they open inside your app instead of on our page: the checkout as an
overlay over your page or inline in your layout, and the customer portal as an overlay. Your page
gets an event for each step.

## 1. Allow your website

A session can open only inside a website on your list. Add each origin (scheme, host and port,
no path) under **Settings → Checkout → Embed on your website**, or with the API:

::endpoint{method="PUT" path="/v1/businesses/{biz}/settings/embedding"}
::

```bash
curl -X PUT $TMBILLING_URL/v1/businesses/$BIZ/settings/embedding \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" -H "Content-Type: application/json" \
  -d '{ "origins": ["https://app.example.com"] }'
```

Use https. `http://localhost` works in a test business only. The usage widget uses the same list.
When you remove a website, its embeds stop on the next page load.

## 2. Create the session with `embed_origin`

Name the website the session opens in. It must be on the list.

```bash
curl -X POST $TMBILLING_URL/v1/businesses/$BIZ/checkout_sessions \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" -H "Content-Type: application/json" \
  -d '{
    "items": [{ "price": "pro-monthly-usd", "quantity": 1 }],
    "embed_origin": "https://app.example.com"
  }'
```

A portal session takes the same field (API links only, not emailed links):

```bash
curl -X POST $TMBILLING_URL/v1/businesses/$BIZ/customers/$CUS/portal_sessions \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" -H "Content-Type: application/json" \
  -d '{ "embed_origin": "https://app.example.com", "forward_url": "/portal?tab=methods" }'
```

A session without `embed_origin` works only as a hosted page.

## 3. Open it in your page

Load the script once. `GET /v1/businesses/{biz}/settings/embedding` returns its `script_url` and
`script_integrity`; the settings page shows the whole tag.

```html
<script src="https://api.example.com/js/v1/embed.js" integrity="sha384-…" crossorigin="anonymous"></script>
```

```js
// Overlay over your page. Escape and the close button close it.
const checkout = TMB.checkout.open({ url: session.url });

// Or inline, in your own layout. The frame takes the height of its content.
TMB.checkout.mount("#checkout", { url: session.url });

// The customer portal, as an overlay.
const portal = TMB.portal.open({ url: portalSession.url });

checkout.on("success", (e) => refreshPlan(e.subscription));
portal.on("subscription_changed", (e) => refreshPlan(e.subscription));
```

## Events

| Event | From | Detail |
|---|---|---|
| `loaded` | both | — |
| `step` | checkout | `{ step: "details" \| "payment" \| "done" }`, once per change |
| `success` | checkout | `{ session, subscription, paid }` |
| `subscription_changed` | portal | `{ subscription, change }`: `plan`, `plan_change_scheduled`, `cancel`, `pause`, `resume`, … |
| `payment_method_changed` | portal | `{ change: "added" \| "removed" }` |
| `invoice_paid` | portal | `{ invoice }` |
| `close` | both | `{ reason: "user" \| "success" }` |
| `error` | both | `{ code: "cookies_blocked" \| "frame_blocked" }` |

Events carry ids only. Grant access from the [webhook](/help/developers/webhooks), not from an
event in the browser.

## What the buyer sees

- **A payment the provider holds.** Some payments take time to confirm (a PayPal review, a bank
  debit). `success` then comes with `paid: false` and the overlay stays open on "Payment in
  progress". If the payment confirms within about 20 seconds, `success` comes again with
  `paid: true` and the overlay closes. Otherwise the webhook tells your server.
- **Provider pages.** PayPal approval, bank pages and other provider redirects open in a new tab,
  because a provider page never loads inside a frame. The buyer approves there, returns, and
  selects **Continue after approval**.
- **A browser that blocks the session.** Safari before 26.2 does not keep the session cookie in a
  frame. The overlay then offers **Open in a new tab**, with the same session, and sends
  `error` with `cookies_blocked`.
- **Phones.** Below 600px wide the overlay fills the screen.
