**Goal:** move your catalog, customers and subscriptions from your current system in one import
that you can check before it writes, and undo after. Customers keep paying on the dates they
already pay, with the cards they already saved.

An import has four steps: upload the files, read the check, start, and read the results. Nothing
is written to your billing data until you start.

This recipe uses the API. To import the same files in the dashboard, with no code, see
[Import your data](/help/guides/import-your-data).

## The files

Upload one CSV file for each kind of record. Every file is optional; a subscription can use
customers, prices and coupons that are in the business already.

| File | One row is | Required columns |
|---|---|---|
| `plans` | a price of a plan | `price_id`, `name`, `currency`, `interval`, and `amount` (or `tiers`) |
| `addons` | a price of an add-on, or a one-time charge with no `interval` | `price_id`, `name`, `currency`, and `amount` (or `tiers`) |
| `coupons` | a coupon | `coupon_id` (the code), `discount_type`, and `percent_off` or `amount_off` |
| `customers` | a customer, with an optional saved card | `customer_id` |
| `subscriptions` | an item of a subscription: rows with the same `subscription_id` are one subscription | `subscription_id`, `customer_id`, `price_id`, `current_term_end` |

History is optional. Add it to keep invoices, payments, credit and usage from your current system:

| File | One row is | Required columns |
|---|---|---|
| `invoices` | a line of an invoice: rows with the same `invoice_id` are one invoice | `invoice_id`, `customer_id`, `status` (`paid`, `open` or `void`), `currency`, `date`, `total`, `line_description`, `line_amount` |
| `credit_notes` | a credit note on an invoice | `credit_note_id`, `invoice_id`, `currency`, `date`, `total` |
| `payments` | a payment, or a refund of a payment in the same file | `transaction_id`, `customer_id`, `amount`, `currency`, `date` |
| `usage` | usage of a usage price that is on a subscription | `usage_id`, `subscription_id`, `price_id`, `quantity`, `timestamp` |

An invoice's lines, less its `discount`, plus its `tax`, must make its `total`; put `tax` and
`discount` on the first row of the invoice. A payment or a credit note names an invoice from the
same import or from an earlier one into this business. A usage price is created in the business
first: the files do not create one.

Download a template with every column and an example row:

```bash
curl $TMBILLING_URL/v1/businesses/$BIZ/imports/templates/subscriptions \
  -H "Authorization: Bearer $TMBILLING_API_KEY" -o subscriptions.csv
```

Add `?format=json` to get each column's accepted values and help.

Your columns do not need our names. Columns are matched to fields by name, in any case and with
any punctuation; `Customer ID`, `customers.id` and `customer_id` all match, and a `(UTC)` suffix is
ignored. Amounts are in the currency's main unit (`49.00`). A date alone (`2026-12-15`) is midnight
in the business's time zone; a date and time with no offset is UTC.

A saved card is a reference to a card that your payment gateway already stores:
`payment_gateway`, `gateway_customer_id` and `gateway_payment_method_id`. The file never contains a
card number.

## Upload

```bash
jq -n --rawfile plans plans.csv --rawfile customers customers.csv --rawfile subs subscriptions.csv '{
  files: [
    { entity: "plans", filename: "plans.csv", content: $plans },
    { entity: "customers", filename: "customers.csv", content: $customers },
    { entity: "subscriptions", filename: "subscriptions.csv", content: $subs }
  ]
}' | curl -X POST $TMBILLING_URL/v1/businesses/$BIZ/imports \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d @-
```

The response is the import with `status: "checking"`, and for each file the column mapping that
was found (`files[].mapping`) and the required fields that no column fills
(`files[].missing_required`). A file can have up to 50,000 rows. Our JSON file is accepted too:
upload it as one file with `entity: "json"`.

## Read the check

The check runs in the background. Retrieve the import until `status` is `checked`:

```bash
curl $TMBILLING_URL/v1/businesses/$BIZ/imports/$IMPORT \
  -H "Authorization: Bearer $TMBILLING_API_KEY"
```

`summary` is the review:

- `entities`: for each file, the rows that are `new`, `existing` (in the business already; kept as
  they are), `invalid` and `excluded`.
- `mrr`: the monthly recurring revenue that arrives, per currency.
- `payment`: customers with a saved card at a gateway that is connected to this business, at one
  that is not, and with no card. A card works only at the gateway account that saved it: connect
  the same account before the first renewal.
- `renewals`: the first and last renewal dates, and how many renew in the next 24 hours.
- `blockers`: each one stops the start. `warnings` do not.
- `history`, when the files carry it: the new invoices, the open ones and what they still owe per
  currency (opening receivables), the credit that refundable credit notes leave per currency, and
  `next_invoice_number` when the imported invoice numbers move your next number.
- `not_imported`: what no import carries (tax rates, gateway credentials, dunning rules, invoice
  numbering, email templates). Set them up before the first renewal.

Each row with a problem has its errors, by column:

```bash
curl "$TMBILLING_URL/v1/businesses/$BIZ/imports/$IMPORT/rows?state=invalid" \
  -H "Authorization: Bearer $TMBILLING_API_KEY"
```

Or download a file as you uploaded it, with an `import_errors` column added. Correct it and upload
it again:

```bash
curl $TMBILLING_URL/v1/businesses/$BIZ/imports/$IMPORT/files/customers \
  -H "Authorization: Bearer $TMBILLING_API_KEY" -o customers-errors.csv
```

To change the mapping, or to leave out the rows with errors (and the rows that need them), check
again:

```bash
curl -X POST $TMBILLING_URL/v1/businesses/$BIZ/imports/$IMPORT/check \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "mapping": { "customers": { "Mail": "email", "Notes": null } },
    "options": { "skip_invalid_rows": true, "exclude_renewing_within_24h": true }
  }'
```

An open invoice imports as owed, and nothing collects it: your current system may still be
collecting it. To have your retry schedule collect open invoices from their due date, check again
with `"collect_open_invoices": true`. A card on file is then charged at the next retry, also for an
invoice that is past due.

## Start

```bash
curl -X POST $TMBILLING_URL/v1/businesses/$BIZ/imports/$IMPORT/start \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{ "confirm": "Your business name" }'
```

`confirm` is required for a live business: the business's name, exactly. The rows are checked
again, then imported in the background. When `status` is `succeeded` (or `partially_failed`), each
row has its `outcome`: `created`, `unchanged`, `failed` with the reason, or `excluded`. The file
download now has an `import_result` column too. The member who started the import gets an email
when it ends.

## Undo

```bash
curl -X POST $TMBILLING_URL/v1/businesses/$BIZ/imports/$IMPORT/undo \
  -H "Authorization: Bearer $TMBILLING_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{ "confirm": "Your business name" }'
```

Undo deletes the records the import created. Records that were in the business before stay. Undo
is possible until billing touches one of those records: an invoice, a payment, usage, a plan
change, or an edit after the import. Retrieve the import to see `undo_blockers` before you ask.

The ledger is never edited. The opening balances an import posts (what open invoices owe, and
credit from refundable credit notes) are reversed with new entries, and the documents are
deleted. Undo does not move your next invoice number back.

## What the import guarantees

- **Nobody is charged twice.** The import raises no invoice and charges nobody. Each subscription
  renews for the first time at its `current_term_end`. Stop renewals in your current system for the
  same dates. A date in the past is an error. Open invoices are collected only with
  `collect_open_invoices`.
- **History is a record, not new revenue.** Paid invoices, payments and refunds are kept for
  reference on each customer; only open invoices and unused credit open balances in the ledger.
- **No emails or webhooks** go out for imported records.
- **You can run it again.** Rows are matched by their id. A row that is in the business already is
  kept as it is and shows as `existing`.
- **Who can import:** owners and admins, or a custom role with the `imports:manage` permission.
  Every upload, start, run and undo is in the audit log.
