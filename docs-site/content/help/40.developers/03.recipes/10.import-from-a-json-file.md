**Goal:** your customers keep paying on the dates they already pay, with the cards they already
saved, and nobody is charged twice for the period they have already paid for.

On a self-hosted install, you export your plans, customers and subscriptions from your current
system into one JSON file and run the importer. The importer is part of the open-source repository.

You can also upload the same file through the API, with a check before it writes and an undo
after: see [Import from CSV files](/help/developers/recipes/import-from-csv-files) and upload it with
`entity: "json"`.

::note{title="On Two Minute Billing Cloud"}
We run the migration for you, including invoice history, coupons and add-ons. Contact us before
you plan the move.
::

## Write the file

The file has three arrays. Amounts are integers in minor units (`4900` is $49.00) and dates are
ISO-8601.

```json [my-export.json]
{
  "plans": [
    { "id": "pro_monthly", "name": "Pro", "amountMinor": 4900, "currency": "USD", "interval": "month" }
  ],
  "customers": [
    {
      "id": "cust_0001",
      "email": "jordan@example.com",
      "name": "Jordan Lee",
      "paymentMethod": {
        "provider": "stripe",
        "providerCustomerId": "cus_XXXXXXXXXXXX01",
        "providerPaymentMethodId": "pm_XXXXXXXXXXXX01",
        "brand": "visa",
        "last4": "4242"
      }
    }
  ],
  "subscriptions": [
    {
      "id": "sub_0001",
      "customerId": "cust_0001",
      "planId": "pro_monthly",
      "quantity": 1,
      "status": "active",
      "currency": "USD",
      "currentTermEnd": "2027-01-15T00:00:00Z"
    }
  ]
}
```

| Array | Fields |
|---|---|
| `plans` | `id`, `name`, `amountMinor`, `currency`, `interval` (`day`, `week`, `month` or `year`), `intervalCount` (optional) |
| `customers` | `id`, `email`, `name`, `paymentMethod` (all optional except `id`) |
| `subscriptions` | `id`, `customerId`, `planId`, `currentTermEnd`, and optional `quantity`, `status` (`active`, `trialing`, `paused`, `canceled` or `non_renewing`), `currency`, `currentTermStart`, `trialEnd` |

Every row also accepts `createdAt` and `updatedAt`. Send them, and imported records keep the dates
from your current system instead of the import date.

The `paymentMethod` is a reference to a card that your payment gateway already stores: the
gateway's customer id and payment method id. The file never contains a card number.

## Run the import

Run these commands from a checkout of the repository, with the same `.env` as your engine.

::steps
### Connect your payment gateway

In the dashboard, connect the **same** gateway account that stores your customers' cards. The
importer links each card to an active account of the same provider. A card token works only at
the account that saved it.

### Find your business id

Open your business in the dashboard. Its id starts with `biz_` and is in the address bar:
`/businesses/biz_…/`.

### Check the file

```bash
pnpm migrate:json my-export.json --dry-run
```

The dry run validates every row and counts the customers that carry a card. It writes nothing.

### Import

```bash
pnpm migrate:json my-export.json --business biz_XXXXXXXXXXXX
```

The run ends with the number of invoices and payments it made. Both are 0.
::

Without `--business`, the importer creates a new organization and business and
prints an API key for it. Nobody can sign in to that organization from the dashboard yet, so
import into your own business unless you only want to look at the result.

## What the import guarantees

- **Nobody is charged twice.** The import raises no invoice. Each subscription renews for the first
  time at its `currentTermEnd`. Stop renewals in your current system for the same dates.
- **Saved cards keep working.** The first renewal charges the linked card. A customer without a
  card goes into dunning at renewal until they add one.
- **You can run it again.** Records are matched by the `id` in your file. A second run finds the
  same records and charges nothing. If you connected your gateway after the first run, run the
  import again to link the cards.

## What the file does not carry yet

The JSON file holds flat-price plans, one plan per subscription and one card per customer. It does
not carry add-ons, coupons, tiered or usage prices, addresses, tax ids or past invoices. Set those
up in the dashboard or through the API after the import. Tax rates and registrations never come
over in any import: configure them before the first renewal, or new invoices raise no tax.
