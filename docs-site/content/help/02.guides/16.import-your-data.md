Bring your plans, customers and subscriptions over from your current system with CSV files.
Nothing changes in your business until you have read what the import does and started it, and
an import can be undone until billing touches what it added.

Open **Settings › Import and export data**, or select **Import customers** on the Customers list (or
**Import subscriptions** on the Subscriptions list). Importing needs an owner or an admin.

## What you can import

One CSV file for each kind of record. Every file is optional: a subscription can use plans,
coupons and customers that are in the business already.

| Section | One row is |
|---|---|
| Plans and prices | a price of a plan: flat, per unit or tiered |
| Add-ons | a price of an add-on, or a one-time charge |
| Coupons | a percentage or fixed-amount coupon with its code |
| Customers | a customer, with address, tax ID and a reference to a card saved at your payment gateway |
| Subscriptions | an item of a subscription: one row for each item, with its quantity, coupons, trial and current term |

You can also bring the history, under **History** on the same screen:

| Section | One row is |
|---|---|
| Invoices | a line of a paid, open or void invoice: one row for each line, with the invoice's total, tax and discount |
| Credit notes | a credit note on an invoice, with the credit the customer can still use |
| Payments and refunds | a payment, with the invoice it paid, or a refund of a payment in the same file |
| Usage | usage of a usage price that is on a subscription |

A payment or a credit note names an invoice from the same import or from an earlier one. Create
a usage price in the business before you import its usage.

Each section has a **Template** with every column and an example row. Columns that have a known
name are matched to their field without a step, so most exports need no changes. You can also
upload the migration JSON file instead of the plans, customers and subscriptions files.

Card numbers are never in a file. A customer's card is a reference to a card saved at your
payment gateway (for example a Stripe customer and payment method ID). Connect the same gateway
account to this business, so renewals can charge those cards.

## How an import runs

::steps

### Upload and check

Select a file for each section, then **Check what changes**. We read every row and compare it
with what is in this business. Nothing is written yet.

### Review

The review shows each row as **New**, **Blocked**, **In this business** (a record with the same ID
is there already and is kept as it is) or **Left out**, with the reason for each blocked row. It
also shows:

- the columns of each file and the field each one is imported as. Change a column, then
  **Check again**.
- the monthly recurring revenue the subscriptions bring, per currency;
- how many customers have a card at a connected gateway, at a gateway that is not connected, or
  no card. A customer with no card gets a payment request at renewal;
- the first and last renewal date. Subscriptions that renew in the next 24 hours are called out:
  stop them in your current system first, or leave them out;
- with history: what the open invoices still owe, the credit customers can use, and your next
  invoice number when the imported numbers move it;
- what no import carries: tax rates, payment gateway credentials, dunning rules, invoice
  numbering and email templates. Set these up in the business.

**Open invoices** import as owed, and nothing collects them, because your current system may still
be collecting them. To have your retry schedule collect them from their due date, select
**Collect them** in the review. A card on file is then charged at the next retry, also for an
invoice that is past due. You can also collect an invoice later with **Collect payment** on the
invoice.

Correct a blocked row in your file and upload it again, or select **Leave out blocked rows**. A row
that needs a left-out row (a subscription of a left-out customer) is left out too.

### Import

Select **Start the import**. In a live business, type the business name to confirm. The import
runs in the background: you can close the page, and the person who started it gets an email when
it ends. Imported records send no emails or webhooks, and the import charges no customer.

### Read the results

The results list each row as **Added**, **Not changed**, **Left out** or **Failed**, with the reason.
**Download results** gives each file back with an `import_result` column.

::

## Undo an import

Open the import from **Past imports** and select **Undo import**. This deletes the records the
import added, and nothing else. You can undo an import until the first renewal, invoice, payment
or change on a record it added; after that, the page says what stops the undo.

If the import brought open invoices or credit, the undo reverses their opening balances in the
ledger with new entries; nothing is deleted from the ledger. An undo does not move your next
invoice number back.

## Good to know

- An import adds records. It does not change a record that is in the business already.
- Importing the same file again adds only the rows that are new since the last import.
- The dashboard takes up to 14 MB of files in one import, and 50,000 rows in each file. For larger
  files, use the API: see [Import from CSV files](/help/developers/recipes/import-from-csv-files).
- **Past imports** keeps every import with who started it and when. The audit log records each
  upload, start and undo.
- When an import or an undo ends, the person who started it gets an email.
- To take your records out as files in the same columns, see
  [Export your data](/help/guides/export-your-data).
