Time Travel moves the clock of a test business forward, so you can watch renewals, trial ends and
failed-payment retries happen in seconds instead of weeks.

Switch to test mode and open **Time Travel**.

## How to use it

::steps

### Start the clock

Select a start date and **Start Time Travel**. Test mode now runs on a simulated clock, and the
real billing clock skips it.

### Travel forward

Move the clock forward. Everything that would have happened in that time happens now: trials
ending, renewals, invoices raised, payments collected, retries run and webhooks sent. Each step
renews a subscription at most once, so keep each step no longer than your shortest billing
period.

### Look at the results

Invoices, subscriptions and logs all reflect the simulated time — so you see exactly what your
customers would have experienced.

### Stop when you are done

Test mode returns to the real clock. Stopping permanently deletes the simulated customers,
subscriptions, invoices, payments, credit notes and events. Your catalogue, coupons, tax rates,
settings, gateways, API keys and webhook endpoints stay, so you can start a new run with the same
set-up.

::

## What it is worth testing

| Scenario | How |
|---|---|
| A trial converting | Subscribe with a trial, travel past its end, check the first invoice |
| A renewal | Travel a full period forward and check the invoice and the charge |
| A failed payment, end to end | Use card `4000 0000 0000 9995`, then travel through your whole retry schedule to see what your customer receives at each step and what happens when it runs out |
| A price change | Change a subscription mid-period and check the proration is what you told the customer |
| Metered billing | Record usage, travel past the period end, check what was billed |

::warning{title="The clock only goes forward"}
You cannot go back to an earlier date. To run a scenario again, stop Time Travel and start a new
run.
::

::note{title="Test mode only"}
Time Travel is not available in live mode.
::
